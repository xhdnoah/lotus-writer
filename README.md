# Lotus

Lotus 是一款基于 Electron 的科幻小说写作桌面软件。左边是章节树，中间是正文，右边是**资料侧边栏**：它会读取当前整章的内容，找出全章值得查证的科学概念，然后列出维基百科等可信来源的条目，可以直接在侧边栏里阅读。

## 运行

```bash
npm install
npm start
```

## 侧边栏怎么找资料

1. **识别概念**（打开一章时立即查询；写作中停笔约 2.5 秒后重新查询整章，概念按在章节里第一次出现的顺序排列）
   - **本地模式**（默认，不需要任何密钥）
     - 描述性说法规则：“宇宙的寿命” → 宇宙的终极命运 / 热寂 / 宇宙年龄
     - 科幻术语表：约 90 个常用概念及其别称（`src/renderer/glossary.js`）
     - `Intl.Segmenter` 中文分词：每个词，以及相邻 2~4 个词的拼接（接住被切碎的专名，如“旅行 / 者 / 2 / 号”→ 旅行者2号）都是候选，再用中文维基的标题、重定向和繁简转换核对是否真有这个条目，并去掉消歧义页
     - 用条目的简短描述（来自维基数据）判断是不是科学概念：描述里有“行星”“探测器”“物理”“基因”等字眼才保留；两个字的词被重定向到别的条目（如“导师”→ 教师）则丢弃
     - 核对过的词记在本机，整章重查时只核对新出现的词
   - **Dify 工作流模式**：用你在 Dify 里配的大模型识别概念。把 `dify/lotus-concepts.yml` 导入 Dify（工作室 → 创建 → 导入应用），在工作流里选一个能用的模型并发布，再在“访问 API”里创建应用的 API Key（`app-` 开头），填进设置，识别方式选“Dify 工作流”。同一章 30 秒内只跑一次；工作流失败时自动退回本地识别，并在侧边栏提示原因
   - **Claude 模式**（在设置里填 Anthropic API Key）：由 `claude-opus-5-5` 把口语化的描述映射成规范的词条名，同时给出英文条目名和一句关联说明
2. **查询来源**
   - 维基百科 · 中文：命中的条目，附摘要和缩略图
   - Wikipedia · English：通过跨语言链接找到对应的英文条目
   - arXiv：先按标题、再按摘要检索相关论文
   - Dify 知识库（可选）：你自己的设定集和资料，见下文
3. **阅读与收藏**：点卡片在侧边栏里打开清理过的条目正文，正文里的维基链接也在侧边栏里跳转；📌 把条目收进本书的“资料夹”。

点上方的概念标签可以暂时排除这个概念，↻ 会重新查询本章。

## Dify 知识库

可以把自己的设定集、资料笔记放进 Dify 知识库，作为侧边栏的一个资料来源（“Dify 知识库”一组卡片）：

1. 在 Dify 的“知识库 → 服务 API”里创建**知识库 API Key**（以 `dataset-` 开头，不是应用的 Key）
2. Lotus 设置里勾选“Dify 知识库”，填 API 地址（Dify 云是 `https://api.dify.ai/v1`，自部署填自己的地址）、知识库 ID（知识库网址里的 UUID）和 Key，点“测试连接”确认
3. 每次查询本章时发最多 4 次检索：本章概念名拼成的 1 次，加上最多 3 段原文（每段截前 240 字）；合并去重后按相关度列出前 12 条
4. Dify 免费版有请求频率上限：同一章 60 秒内只检索一次；被限频时暂停检索 2 分钟，把额度留给同步；知识库配置的重排模型额度用完时，自动改用不重排的向量检索

检索方式、Top K 和阈值都用知识库自己在 Dify 里的配置。设定集里的虚构名词维基百科查不到，所以段落本身也会拿去检索。

## 世界观设定

右侧栏的“世界观”标签页（在“资料夹”右边）用来记录这个宇宙里成立的设定，比如“冰的密度大于水”“这个恒星系有三颗恒星”：

- 点“新建设定”，在卡片里写名称和内容，停笔就自动保存
- 每条设定存成作品文件夹 `世界观/` 目录下的一个 Markdown 文件，和章节一样受 git 分支管理
- 开启 Dify 后，所有设定合成一个文档“世界观设定.md”同步进知识库，每条设定是其中一个小节；文档开头注明“这是本作品的虚构设定”，检索时能和真实科学区分开

## 同步到 Dify 知识库

开启 Dify 且勾选“自动把章节和世界观设定同步到这个知识库”（默认关闭，需主动勾选）后：

- 每章是一个文档“01 章节标题.md”（序号和 Markdown 文件名一致；Dify 的文档列表只能按上传时间排，序号让顺序一目了然，调整章节顺序后序号会跟着更新），所有世界观设定合成一个文档“世界观设定.md”；空章节、名称和内容都空的设定不上传（只写了名称的设定也会同步）
- 停笔 30 秒后同步一次，切换章节时立即同步；只上传内容有变化的项
- 删除章节或设定，知识库里对应的文档也会删除；第一次同步时，知识库里同名的已有文档会被认领，不会重复创建
- 编辑区标题右边显示“Dify 已同步 / 同步失败”，鼠标悬停可以看到新增、更新、删除了几个文档；失败两分钟后自动重试
- 切换 git 分支时，知识库会跟着变成当前分支的内容
- 每次上传都会触发 Dify 重新索引，消耗额度

## 限流与重试

请求维基百科和 arXiv 时会按站点排队：维基百科最多同时 2 个请求，arXiv 每 3 秒 1 个。

- 被限流（429/503）时，按服务器给的 Retry-After 或指数退避（2、4、8…秒，单次最多 30 秒）自动重试，最多 6 次；同一站点的其他请求也一起暂停
- 还是失败的话，侧边栏会保留上一次的结果，显示“维基百科限流，N 秒后重试”，分别在 20、45、90 秒后自动重查
- 三次都失败才显示错误，点 ↻ 可以手动重试

## Markdown 文稿

每个章节实时保存成一个 Markdown 文件：停笔约 0.4 秒就落盘，关闭窗口前也会先把没写完的内容写下去。

- 默认位置：`~/文稿/Lotus/<作品名>/`，文件名是 `01 第一章 · 标题.md`，内容是 `# 标题` 加正文
- 改章节标题或调整顺序，文件会跟着改名；删除章节，对应文件会移到废纸篓
- 启动时以文件夹里的 Markdown 为准：在别的编辑器里改过、或新建了 `.md` 文件，都会读进来
- 设置里可以“打开”这个文件夹，也可以“更改”到别的文件夹；菜单“文件 → 在 Finder 中显示文稿”也能打开它
- `.lotus.json` 记录章节和文件名的对应关系，不要手动删除它

## 分支与版本（git）

文稿文件夹本身就是一个 git 仓库（用的是系统自带的 git）。点左栏作品名下面的 `⎇ main` 打开分支面板：

- **从当前新建**：从当前稿件分出一条新线，比如“结局B”，在上面随便改，不影响主线
- **切换分支**：点分支名，编辑器里的章节会换成那条线的稿件
- **保存版本**：把当前状态存成一个版本，可以写一句说明；“最近版本”列出最近 15 个版本
- 切换或新建分支前，未保存成版本的改动会自动存成一个版本，所以不会丢
- 分支名旁的黄点表示有改动还没存成版本

分支合并目前还要在终端里用 git 自己做。

## 缓存

查过的维基百科和 arXiv 内容都会存到本机（`~/Library/Application Support/Lotus/lotus-cache/`），包括条目摘要、搜索结果和阅读器里的正文：

- 7 天内再查同样的内容，直接用缓存，不发请求，重启后也有效
- 过了 7 天会重新拉取；如果这时断网或被限流，就退回旧缓存，状态栏显示“离线 · 缓存”
- 设置里可以看缓存条数和大小，也可以一键清空；超过 5000 条时自动删掉最旧的

## 角色取名（隐藏功能）

点左栏的“章节”二字，或者按 `⌘⇧N`（Windows/Linux 上是 `Ctrl+Shift+N`），会弹出取名面板：

- 风格：中文、西式、日式、星际代号
- 性别：随机、男、女、中性
- 点名字插入到光标处，按住 ⌥ 点击则复制，↻ 换一批，Esc 关闭

## 结构

```
src/main.js            主进程：窗口、存储、受限的网络代理（只允许访问 wikipedia.org / arxiv.org）、响应缓存与限流重试
src/ai.js              Claude 概念识别（结构化 JSON 输出）
src/cache.js           维基百科 / arXiv 响应的磁盘缓存
src/throttle.js        按站点排队限速，被限流时整站冷却
src/dify.js            Dify 知识库检索
src/difysync.js        章节和世界观设定同步进 Dify 知识库
dify/lotus-concepts.yml  Dify 概念提取工作流（DSL，可直接导入）
src/files.js           章节 ⇄ Markdown 文件（写入、改名、删除、读回）
src/git.js             文稿文件夹的 git 操作（分支、版本、历史）
src/preload.js         contextBridge 接口
src/renderer/          界面：app.js（编辑器/章节）、research.js（侧边栏）、sanitize.js（维基 HTML 白名单清洗）、names.js（取名）
```

数据保存在 `~/Library/Application Support/Lotus/`（`project.json`、`settings.json`）。

## 冒烟测试

```bash
LOTUS_SMOKE=/tmp/lotus-smoke LOTUS_SMOKE_TEXT='舰长下令启动曲速引擎……' npx electron .
```

这条命令会用独立的数据目录启动应用，等侧边栏查出结果后打印侧边栏文字，打开第一张卡片，然后把截图存成 `smoke.png` 和 `reader.png`；接着测试取名面板（截图 `names.png`）。加上 `LOTUS_SMOKE_429=N` 让前 N 次请求假装被限流；加上 `LOTUS_SMOKE_OFFLINE=1` 可以模拟断网，用来检查缓存；加上 `LOTUS_SMOKE_GIT=1` 会再测一遍新建分支、改稿、切回主线（截图 `branches.png`）。
